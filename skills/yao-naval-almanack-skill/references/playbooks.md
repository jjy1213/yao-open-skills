# 应用流程与 28 个场景

这里的流程、问题、实验和输出格式均属于本 skill 的应用设计。知识卡编号对应五个主题文件。针对单个问题只读取所需主题，通常使用一至三个原则。

五个主题知识卡的“含义”为书内中文转述；“适用与局限”“误解”“应用”“问自己”为本 skill 的应用设计与提示。除非另有实际核验的来源，不把这些提示写成书中要求。解释时先转述书内含义，再用“结合你的处境，我会检查……”引出应用条件。

## 自动辅助模式

用户提出相关实质问题时，可以直接使用本 skill，无须先说书名、人名或技能名称。适合的任务包括：比较职业与专长发展；减少重复交付、服务产品化与成果归属；评估长期合作及持续投入；调整忙碌却没有积累的时间安排；反思目标取舍、社会比较、自由与现实责任。书中概念的解释、导读和查证仍按下面四种任务执行。

先完成用户要求的交付，再用一至两个相关原则改善依据、现实条件、下一步行动或改判条件。保持用户要求的篇幅、语气和格式；观点用于支持当前问题，避免每次展开全书导读。必要时用一句“结合纳瓦尔关于……的观点”标明所用视角，并给出章节链接；应用建议继续明确归属。

纯润色、排版、翻译、计算、代码实现及泛化规划由对应能力完成。文章涉及职业或创业时，只有用户要求优化实质论证、方案或取舍才使用本 skill；仅改措辞和标点时跳过。泛化焦虑、具体交易与临床治疗保留各自路由。用户说“这轮不用纳瓦尔”“只润色”“只计算”，或指定另一框架单独分析时，遵循本次要求；跨任务不延续旧视角。

自动启用只改变分析与回答，不授予发送消息、外部写入、定时执行或修改用户文件的权限。有关混合任务的实际动作仍遵循用户授权。

## 安装后的启用

将整个技能目录放入宿主支持的技能位置并确认已加载。Codex 支持根据 frontmatter 描述选择相关 skill，本包的 `agents/openai.yaml` 显式允许隐式调用；`agents/interface.yaml` 的 semantic 模式记录通用兼容意图，其他宿主的支持情况需分别确认。参见 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。允许隐式调用不保证每次命中；安装后用实际问题检查读取与答复。显式调用 `$yao-naval-almanack-skill` 仍可保留。

## 四种任务

### 导读与解释

先确定用户想理解的概念、章节或全书范围。直接读取相关主题的知识卡，说明含义、一个有帮助的例子和适用条件；涉及全书范围或出处时再读索引。全书导读按五个主题组织；概念问题直接解释。需要延伸时读取书单，避免把个人哲学说成公认定论。

### 观点与引文核验

先确定待核验的具体措辞与归属，再区分英文原话、中文译文、书中转引和概括。通过来源索引定位，必要时联网读取原始访谈、文章或贴文。输出可核验内容、出处和仍未确认的部分。网页摘录和本地知识卡只能提供线索，逐字引用需要实际核验；不同中文版本的页码不混用。

### 实际问题分析

1. 用用户已有事实明确目标、选项和现实限制。
2. 缺少影响结论的事实时，最多补问三个问题；能继续的部分先分析。
3. 选择少量原则，解释它们与当前问题的关系。
4. 检查需求证据、成本、条件和反例，分开事实与推断。
5. 给出一个倾向判断、一至三个小行动，以及会改变判断的条件。

不要给每个问题强加表格、评分或完整人生方案。信息不足时提供条件判断，避免自行补造收入、客户、经历和资源。

### 复盘与反思

先回顾实际行动和结果，分开可控制的选择、环境影响与随机因素。用少量原则找到需要保留或调整的行为。复盘粒度由问题决定，不要求每日量化幸福。用户要求定时提醒、周期执行或外部保存时，交由对应能力处理；本 skill 本身不创建自动任务或持久记忆。

## 应用模板

模板用于检查完整性，最终表达按问题调整。

**推荐判断**：我倾向于什么，适用哪些事实和限制。

**依据**：一至三个相关原则，说明书内转述或官方扩展，并给出对应章节或来源链接。用户看到可读的章节名，知识卡 ID 用于内部定位。直接引用时附实际核验来源；链接本身不代表已完成逐字核验。

**验证行动**：用户现在能进行的小尝试，观察什么结果。

**改判条件**：什么新事实、代价或反馈会改变建议。

## 现代应用与资料缺口

AI 自动化、GEO 服务产品化、数字课程与今天的平台规则属于现代应用推演。先解释与 W02、W05、W06 等原则的联系，再用用户的真实交付、权限和成本验证；不要写成书中已提出的具体方案。只有需要最新事实或原话核验时联网，不要求用户先注册额外账户。
