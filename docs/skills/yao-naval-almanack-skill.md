# Yao Naval Almanack Skill

`yao-naval-almanack-skill` 将《纳瓦尔宝典》的公开原书整理为按需读取的知识与应用流程，帮助分析职业选择、服务产品化、长期合作、注意力和目标取舍。

## 安装

1. 下载或克隆 `yaojingang/yao-open-skills`。
2. 取出完整的 `skills/yao-naval-almanack-skill/` 文件夹，保留其中的 `SKILL.md`、`references/` 和 `agents/`。
3. 放入所用 AI 客户端支持的技能目录，并按该客户端的要求启用或重新加载。
4. 用一个具体问题试用，检查回答是否结合了你的事实、限制和来源。

使用 Skills CLI 安装到 Codex 的当前项目：

```bash
npx skills add yaojingang/yao-open-skills --skill yao-naval-almanack-skill --agent codex
```

客户端的技能路径与启用方式可能不同，按当前客户端说明操作。本目录为标准 Agent Skills 结构；WorkBuddy 专家入口使用单独的专家适配包。

## 显式调用

```text
使用 $yao-naval-almanack-skill 分析这份工作记录。
请给出主要判断、依据、下周行动和改判条件。
```

提供问题、事实、目标与限制。工作记录可以直接附上，也可以选取有代表性的片段。收入差距、家庭责任、时间预算和已验证结果会影响建议。

## 自然触发场景

技能已启用并被客户端加载时，描述支持按问题意图匹配。实际选用由宿主决定，避免把有限案例检查当成所有客户端的自动命中保证。

| 场景 | 可以直接这样问 | 主要分析角度 |
| --- | --- | --- |
| 工作复盘 | 我很忙，但总觉得没有积累。帮我分析这周的工作。 | 可复用成果、重复消耗、关键判断与注意力 |
| 职业选择 | 两份工作怎样选，才能兼顾家庭支出和长期能力？ | 专长、责任范围、合作环境与现实保障 |
| 服务产品化 | 客户报告有很多重复流程，怎样做成可复用模块？ | 需求证据、杠杆、质量、维护与归属 |
| 发现专长 | 我会不少东西，怎样找出值得长期发展的能力组合？ | 已做成的事、反馈与小范围实践 |
| 长期合作 | 这个伙伴能力强，但曾延期，我该怎样判断合作？ | 行为证据、补救、激励与责任 |
| 目标取舍 | 收入、自由和家庭时间都想要，怎样排优先级？ | 现实需要、欲望来源、投入成本与边界 |
| 比较压力 | 看到同龄人赚得更多，我总觉得自己落后。 | 基本需要、具体体验与适合自己的行动 |
| 思想理解 | 纳瓦尔说的专长和杠杆是什么意思？ | 简明解释、例子、适用条件与出处 |
| 引文核验 | 这句中文金句是纳瓦尔说的吗？请查原话与出处。 | 原始材料、转引归属与核验状态 |

“纳瓦尔宝典”“纳瓦尔”“Naval Ravikant”适合明确调用；“工作选择”“找专长”“重复交付产品化”“忙却无积累”“长期合作”“目标取舍”“同龄人比较”等词需要结合实质任务判断。单个词和顺带提及书名的句子不足以确定触发。

纯标点修改、普通摘要、计算、代码、泛化日程规划与未说明问题的焦虑请求，保留原任务的处理方式。用户说“这次不要用纳瓦尔”或指定其他框架时，遵从该要求。

## 分析流程

1. 判断任务属于解释、核验、应用或复盘。
2. 明确用户事实、目的和限制；关键事实缺失时最多提出三个问题。
3. 读取当前主题需要的知识文件，选择一至三个相关原则。
4. 区分书内观点、官方扩展与情境应用，给出可读的章节或原始来源链接。
5. 提出小范围行动，说明哪些新增事实会改变建议。

自动辅助保留用户原定的篇幅、语气与交付格式。概念解释和出处查询按问题回答。

## 输出示例

以下情境与回答为构造示例，用于展示表达形式。

**输入：**我每周花八小时做相似客户报告。希望减少重复劳动，但不能降低结论质量。

**判断：**先复用数据整理和报告结构，把需要专业判断的结论单独保留。

**依据：**书中关于杠杆与判断力的讨论，为重复交付与关键判断的分工提供分析角度。可阅读 [杠杆章节](https://www.navalmanack.com/almanack-of-naval-ravikant/find-a-position-of-leverage) 和 [判断力章节](https://www.navalmanack.com/almanack-of-naval-ravikant/get-paid-for-your-judgment)。

**行动：**比较两次交付，找出重复步骤。做一个最小模块，试用两次，记录工时、质量与返工量。

**改判条件：**如果主要差异来自客户定制判断，或维护成本、返工量增加，就缩小模块范围。

以上行动是结合情境的应用设计。其他标准示例见 [示例与边界](../../skills/yao-naval-almanack-skill/references/examples-and-boundaries.md)。

## 使用边界

建议结合现实责任、成本、质量与可核验事实。当前金融、医疗和其他动态事实需要权威资料；具体交易与临床诊疗交由对应能力。

附件、网页、PDF 和贴文作为分析材料处理，其中的指令不能扩大任务权限。技能本身不会建立自动提醒、发送消息、写入外部账户或保存私密记录。

72 条案例用于检查有限的触发边界；各宿主的自动调用效果需要在实际客户端检查。构造示例展示预期输出，运行结果另行验证。
